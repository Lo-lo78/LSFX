# LSFX 0.0.1 TEST25
Experimental accessible VST3 instrument for REAPER. TEST25 adds a stereo-linked 1176-inspired parallel compressor for each MIDI channel (SFZ in the normal build; SF2 in an opt-in experimental multigroup build). TEST24 removes standalone speech fallbacks, restores focus across editor sessions and import dialogs, and adds SFZ instrument gain per virtual program. TEST23 added direct SF2/SFZ program import, mixed SF2/SFZ playback and multiple SFZ sources in the virtual map. FluidSynth continues to use the stable single-stereo native rendering path; SFZ uses sfizz 1.2.3 with independent active MIDI-channel instances. The existing plugin identifier and XML state tag remain unchanged. Earlier TEST sections below are historical.

Open SF2 or SFZ using the existing editor. SFZ samples must remain in their original relative locations. Bank and Program controls are available even when the map is empty or an SFZ is loaded. In REAPER's generic parameter UI, SF2 interpolation is Linear / Fourth order (default) / Seventh order; SF2 effects are Off (default) / Reverb / Chorus / Both. These settings and the instrument path persist in state. Existing TEST1 states without the new fields use the lighter defaults. Each active SFZ instance uses 128 voices; the shared SF2 synth uses 256 voices; see TEST6 controls below. SF2 idle bypass now waits for no active voices and two seconds below -100 dBFS on both pre-master dry/native-wet and final effects signals; it works with effects enabled and ignores MIDI clock/active sensing. CPU improvement is not measured yet.

Build: push to main and download TEST25 Windows x64 artifact from Actions. The workflow uses JUCE, FluidSynth via vcpkg and recursively fetched sfizz sources. See TESTING.md and THIRD_PARTY.md. Experimental build, not verified on Windows in the authoring environment.

TEST4: retains the TEST3 duplicate cxxopts alias fix and patches the pinned sfizz MSVC runtime to /MD (and /MDd in Debug), matching JUCE and vcpkg static-md. Also normalizes nested sfizz targets and saves build logs even on failure. DSP and editor behavior are unchanged from TEST2.

TEST5: fixes the sfizz license filename in packaging (LICENSE, not LICENSE.md), and records packaging logs. No DSP changes.


## TEST6 - accessible parameter grid

On initial editor entry, focus is requested for Open SF2 or SFZ. The Parameters button immediately follows it. Alt+L opens/focuses the grid, Alt+V focuses its value, Esc or Alt+C closes it. Alt+O (Open), Alt+M (MIDI channel), Alt+K (Bank), Alt+P (Program), Alt+G (Master output gain) focus the named main control without activating it. Alt+A executes Panic; Alt+S announces status without a separate control.

Browse: Up/Down select adjacent parameters; Left/Right and Page Up/Down move five rows; Home/End first/last parameter. Type a letter to select the next matching name (Shift reverses). Enter or Tab goes to the value slider. In the value slider, Up/Down changes the value; Left/Right chooses step 1, 5, 10, 15 or 20; Page Up/Down changes numerical values by step times 40. Enumerated settings and channel selection always change by one. Home/End select the first/last parameter even in value mode. Alt+Home/End set minimum/maximum. Enter returns to the grid; Alt+Up/Down or Alt+Page Up/Down can also edit from the grid. Backspace resets generator offsets or the common engine settings when editing; it does not reset arbitrary CCs. Main output gain uses the same step behavior.

SF2: output gain, selected channel, interpolation, effects, MIDI volume/pan/expression/modulation/FX sends, and per-channel generator offsets for filter, AHDSR, tuning and modulation. Offsets are additive native SoundFont units, not absolute zone values. Zero offset preserves the instrument's programmed values. Some changes affect newly triggered notes; effects sends require effects enabled.

SFZ: output gain, live sample quality and CCs explicitly labeled by the instrument. The loader queries the initial CC values through sfizz's read-only OSC interface before publishing the synth. If a query is unavailable the value is shown as Instrument default (not read), not guessed. An explicit edit sends MIDI CC, and the file is never rewritten. Unlabeled opcodes and keyswitches are not yet a complete instrument editor. SFZ remains single instrument on MIDI channel 1.

State version 3 retains old gain, quality, effects, file and programs. Explicit grid CC and generator edits are saved in the project/preset and restored on load or sample-rate change. Incoming MIDI changes update display; only explicit editor overrides are saved, so MIDI sequences continue to drive their own events. Opening another file starts with its own defaults. No change to tested dependency/packaging fixes; no extra scan of all controls each audio block unless an edit is pending. Dynamic CCs/generator offsets are internal controls, not individual host automation parameters yet.

## TEST7 - GS-style effects, output stage and CPU diagnostics

Effects is now a global switch for either engine. The independent Delay level controls a separate stereo/ping-pong master delay (default off). Eight GS-named reverb types: Room 1/2/3, Hall 1/2, Plate, Delay, Panning Delay. Eight GS-named chorus types: Chorus 1/2/3/4, Feedback Chorus, Flanger, Short Delay, Short Delay with Feedback. Names follow Roland GS; these are LSFX approximations, not exact Sound Canvas algorithms or full GS macro SysEx emulation. SF2 Room/Hall/Plate and Chorus 1-4 use FluidSynth and native per-channel CC91/93 sends. Other variants and independent delay are master inserts; SFZ uses a JUCE reverb and LSFX master delay/modulation, in addition to the SFZ instrument's own internal effects. No per-channel send for these master effects yet. Reverb Delay/Panning Delay use the shared delay time/feedback; Short Delay variants are 35 ms. Chorus rate/depth apply to modulation types, feedback applies to Feedback Chorus, Flanger and Short Delay with Feedback only. Reverb damping, width and time scale apply to Room/Hall/Plate. Defaults are LSFX settings, not Roland numeric presets. All new global parameters are exposed to the host and saved in XML version 4; Backspace resets them in the value editor. Existing states receive defaults.

The final stereo stage is adapted from LJuno-116 0.99.67: peak-linked Glue (1 ms attack, 4 ms release, threshold 0.055, ratio 2:1, gain 0.4), historical soft limiter (0.98 threshold, 0.15 slope), then master gain times 2. An adjustable input trim (0 to +24 dB, default +12 dB) compensates for FluidSynth's low internal level; also applied to SFZ. Soft limiter is not a brick-wall ceiling: high trim/output gain can exceed 0 dBFS. Adjust gain as needed. New output stage changes loudness and dynamics of previously saved projects.

SF2 rendering skips only after no active voices and two seconds below -100 dBFS before the output stage; notes, MIDI controls, patch/effect changes wake it. SFZ keeps rendering because its trigger and internal effect semantics differ. Panic resets local effect state and releases SF2 sustain/sostenuto, then all sounds off; does not explicitly clear FluidSynth native effect buffers. If a MIDI block is lost during engine swap, a panic is requested to avoid stuck notes. Read status reports active engine voices, SF2 idle sleep and cumulative dropped engine-swap blocks. These diagnostics help isolate persistent CPU spikes; the actual root cause is not yet confirmed. No change to the working Windows dependency configuration. Tests/OutputStageTest.cpp is a standalone C++17 regression test for the new stage/delay; tested at 44.1/48/96 kHz. Full Windows build and REAPER behavior still need validation.

## TEST9 - focus, bounded grid, incremental search, output level

The initial focus request now follows LJuno's delayed native-peer readiness approach. It does not force focus out of the host FX chain or away from an already focused editor child; the editor root and title are ignored by accessibility. The grid is prepared before its focus transfer, and the destination is revealed before hiding the old panel. Leaving Parameters through an accelerator goes directly to the requested main control. The file chooser callback no longer forcibly steals focus after returning. Native popup keys remain native. Alt editing uses the actual originating control for its announcement; the timer no longer rewrites unchanged values. Read-only slider text boxes were replaced by visual readouts, leaving one accessible slider per value.

Grid navigation uses eight rows per column, two visible columns per page; borders stop navigation like LJuno rather than wrapping. Up/Down stays within the column, Left/Right moves to the same row of the previous/next column if it exists. Page Up/Down moves five within the column. Home/End go to the first/last parameter of the current column; Ctrl+Home/End go to the first/last parameter of the full grid. Type a prefix within one second to search label/word starts (LJuno's search helper), repeat a single letter to cycle, Shift reverses. The painted grid shows the selected cell and supports mouse selection; the accessible native selector remains the single grid control.

In Value, Up/Down changes the value, Left/Right selects step, Page Up/Down changes numerical values by 40 times the selected step, Home/End sets minimum/maximum. Alt+arrows, Alt+Page and Alt+Home/End perform the same edits directly from Grid without changing focus. The main Output gain slider supports the same step, page and boundary keys, also with Alt. Existing choice settings still advance one option at a time. Backspace resets supported parameters from Grid or Value. Esc closes the grid, native host Escape is not intercepted on the main panel.

The output stage provides an additional factor of 2 (6.02 dB below the final knee) for both SF2 and SFZ, after the existing Glue and master gain. A continuous sample-level soft ceiling starts at 0.90 and approaches 0.999 in either polarity. It is not a true-peak limiter. Existing parameter IDs, gain range, defaults and state format stay unchanged; previously saved projects also sound louder. No changes to the engines, FX, CI dependencies or runtime linking. Standalone C++ output/delay and incremental search tests passed locally; Windows build and actual focus/Alt-key handling in REAPER/NVDA must still be tested.

## TEST10 - VST3 multichannel MIDI Program Change

JUCE 8.0.12's default MIDI mapping has 130 entries per channel (CC, pressure, pitch bend) but no entry for Program Change; its controller lookup lacks the bound check for index 130. LSFX patches the pinned wrapper at configure time, appending sixteen mappings without renumbering existing CCs and providing 16 input-channel units and their 128-program lists for standard VST3 host delivery. Both host paths route to the same MIDI event at its supplied offset. Numeric host program names are bank-independent, while LSFX's editor displays the loaded SF2 preset names. Program numbers are zero-based. SF2 events at identical timestamps are processed as SysEx, bank select, program change, then other events to handle VST3's separate controller queues and event lists. No changes to the sound engines, grid or gain from TEST9. Read status now reports received MIDI program changes and the last channel/program (counts received events, not necessarily successful selection). Wait until the file is loaded before starting playback; events arriving before the engine is ready are not replayed. REAPER delivery and Windows compilation require validation.

## TEST11 - grid selection and MIDI effects reception

The grid now captures the selected ComboBox ID before editing its item texts and synchronizes the label with the same ID afterwards. JUCE otherwise returns -1 for the selection when the displayed text differs from the updated item's text. This affected all value edits, not just Alt keys. No native keyboard hook is used. Alt+Home and Home in Value mode set the maximum; Alt+End and End in Value mode set the minimum, matching LJuno. Plain Home/End in Grid remain first/last. Output gain uses the same maximum/minimum convention.

MIDI effects reception (Follow MIDI, default; Manual) is a new persisted host parameter. Loading a new SF2 with Follow MIDI and Effects Off starts with Both. Incoming nonzero CC91/93 enable their native effect when following MIDI (unless XG has explicitly switched that effect off). The send value is always passed to FluidSynth, on its original channel. MIDI GM/GS/XG resets initialize the supported global effect settings in Follow MIDI. Roland DT1 GS messages with a valid checksum can select reverb/chorus macros, character, levels, time/depth/rate/feedback and basic delay settings; GS part sends use the default GS part/channel mapping. Yamaha XG supports common reverb/chorus types, off, return levels, and multipart sends using the default part/channel mapping. Universal master volume and GS/XG master volume are applied in a separate MIDI gain stage (not the user Output gain parameter). These are translations to LSFX's effects, not exact hardware algorithms. Manual mode preserves manually set global FX parameters; CC sends, master volume and native FluidSynth MIDI messages are still received. Existing SFZ playback is unchanged. Unsupported manufacturer-specific messages continue to be handed to FluidSynth; full GS/XG emulation, separate delay/phaser sends, arbitrary part remapping, insert effects and all parameter addresses are not implemented. The existing custom master effects still do not have per-channel sends. MIDI FX values update the actual parameters without sending host automation gestures from the audio thread. The UI reads them and state version 5 saves the global parameters. Note/CC/program ordering within equal host timestamps now places non-note controllers before notes. Original ordering of multiple RPN/NRPN sequences at the same timestamp cannot be reconstructed from separate VST3 parameter queues. The native engine still has internal rendering block granularity.

Read status adds counters for CC91, CC93, SysEx and applied supported FX/master SysEx. If counters stay at zero, check MIDI event delivery from the host. The standalone Tests/MidiEffectsTests.cpp covers decoding, not actual host delivery. Tests/GM-FX-reception.mid exercises program, CC sends and GS effect type/level changes. The Windows build, actual keyboard behavior and audible result require validation in REAPER.

## TEST12 - channel 10 balance and keyboard-only commands

SF2 channel 10 trim is a persisted host parameter (-12 to +12 dB, default +3 dB). This is an LSFX calibration choice, not a GM/GS requirement. Native FluidSynth defaults measured locally are CC7=100, CC11=127 and CC10=64 on both channels 1 and 10; no CC or note velocity is artificially increased. FluidSynth uses sixteen dry audio groups with one shared native effects group. The dry channel 10 is mixed with a smoothed trim before the master stage; native reverb/chorus sends are not boosted. The remaining channels and SFZ are unchanged by this trim. At 0 dB all dry groups are mixed directly, without the additional channel-10 scratch pass. The extra group buffers may increase active CPU slightly; no extra synthesis instance or audio-thread allocations. The default native gain is explicitly 0.2. SF2 master dynamics offers LJuno Glue (original default) or Linear (soft ceiling) for transient and balance comparisons; the latter preserves low-level gain and final peak protection while bypassing Glue compression and its intermediate limiter. SFZ always retains its previous output stage. New parameter IDs are appended, old state receives defaults; choosing 0 dB and LJuno Glue restores the TEST11 mix behavior. GS part level and XG multipart volume now feed CC7 on the default corresponding channel, including channel 10. Other proprietary drum setup parameters are not fully emulated. Alt+S now speaks current status plus diagnostic counters, including channel 10 CC7, CC11 and bank/program; it does not open a dialog. Alt+A immediately silences voices (Panic) without moving focus. Neither command has a main-panel button. After the native file chooser closes, focus is explicitly restored to Open SF2 or SFZ when the plugin peer is active, with a bounded return request; the filename and loading result are announced when that control retains focus. User navigation takes priority. The Windows/NVDA focus behavior requires testing.

## TEST13 - SoundFont reference calibration

Scoring Synth 1.3 by Chmaha is the reference for the design (unity internal gain, independent native sends, no obligatory master compressor). No JSFX source or sample data is incorporated. FluidSynth gain is 1.0; new instances have master gain 0 dB, input trim 0 dB, drum trim 0 dB, and SF2 master dynamics Reference (unprocessed). Reference does not clamp finite float peaks: lower Output gain if the host clips. Linear (soft ceiling) preserves the low-level unity slope and adds only sample peak protection. LJuno Glue remains available with stereo detector, 1 ms attack, 4 ms release, 2:1 ratio, unity low-level slope and threshold translated to 0.275 for the new gain scale; the historical limiter and final ceiling remain in that mode. SFZ retains its previous final-stage algorithm, but shared defaults for gain, trim and effect settings change for fresh instances. The channel 10 trim is optional and defaults to neutral; no velocity, SF2 attenuation or CC7/CC11 correction is imposed.

Initial effect settings inspired by Scoring Synth: native reverb room size 0.50 (Room 3 / time scale 50), damping 0.30, width 0.80, level 0.70; Chorus 2 with four voices, level 0.55, rate 0.36 Hz, depth 3.6 ms. These are matching numeric settings, not identical effect algorithms. Native MIDI is the default SF2 initial ambience profile (CC91/93 native defaults 0). Optional Scoring ambience sets initial CC91=40 on all channels; an incoming or explicitly edited CC91, including zero, takes precedence until the next MIDI reset. Profile changes only affect channels with no explicit send. Incoming MIDI and SysEx still control effects as before. Native FluidSynth effects keep their own per-voice sends; custom delay/chorus variants remain master inserts, not exact Roland algorithms. No extra reverb instances or copied JSFX DSP.

State version 7 adds the ambience parameter. Existing XML values (including old trim, gain and dynamics selections) are retained; they can sound different under the new gain staging. For a clean comparison use a fresh instance or reset the relevant controls to defaults. Existing dynamics parameter IDs and choice indices 0/1 are retained, but normalized host automation for this parameter may need re-recording because a third choice was appended. The new ambience parameter is appended after the prior host parameters.

## TEST18 - independent stereo output routing

The main editor has two horizontal 16-channel strips between MIDI channel and Master output gain. Alt+U focuses the channel gain strip; Alt+R focuses the routing strip. Each strip is one Tab stop, with Left/Right selecting MIDI channel and Up/Down changing gain or output respectively. Routing Home/Backspace selects Main 1/2, End selects 33/34, Page Up/Down moves four choices. Alt+G focuses Master output gain. The grid's Output gain edits the selected MIDI channel's existing gain, not the master. SF2 retains TEST16's native voice attenuation trim; SFZ uses its existing channel 1 audio gain.

17 stereo VST3 buses (34 mono pins) are declared: Main 1/2 and 16 auxiliary pairs 3/4 through 33/34. Each MIDI channel selects exactly one destination; multiple channels can share it. Routes are host parameters appended after existing IDs and saved in XML version 9, defaulting to Main for older projects. Enable the corresponding host output pins and track channels; a disabled destination is silent rather than silently falling back to Main.

SF2 again uses the multigroup FluidSynth process API, with 32 separate dry planes and four separate wet planes, preallocated in the loader-owned engine and cleared for each chunk of at most 1024 samples. All dry channels are routed once, with a single native shared FX group returned to Main. For separated channels the native chorus and reverb generator sends are suppressed using negative generator offsets, preserving their CC values and restoring native offsets on return to Main. Shared FX already generated before a routing change can naturally decay on Main. The master gain, master dynamics and custom FX affect Main only. Auxiliary outputs retain stereo, channel trim and native synthesis; they bypass these shared FX and master processing. SFZ remains MIDI channel 1 only; its routing bypasses LSFX's shared FX, but any effects programmed internally in the SFZ itself are not removed.

The previous multigroup TEST15 crashed in the Windows host, so the complete Windows VST3 load and playback remain mandatory validation. Local FluidSynth regression confirms output separation, shared destinations and all-main parity with the original single-group stereo renderer, not Windows stability.

## TEST25 — Per-MIDI-channel parallel compressor

Alt+L shows Compressor threshold, ratio, attack, release, gain and mix for the selected channel when its instrument supports the separate dry signal path. Each control announces its channel number. The ranges follow the LJuno-116 compressor model (threshold -60..0 dB; ratios 4:1/8:1/12:1/20:1; attack 20..2000 us; release 20..2000 ms; gain -36..+36 dB; mix 0..100%). The default is threshold -11 dB, ratio 4:1, attack 1000 us, release 250 ms, gain +7 dB, mix 0%. The zero mix is an exact bypass and is used by old states. This is a digital stereo-linked RMS compressor inspired by 1176 and LJuno, not a component-level emulation of a FET circuit. No external sidechain or distinct all-buttons mode.

Each channel's gain/trim is applied before its compressor and before output routing. Each channel has its own detector and envelope, so two channels assigned to the same stereo output are compressed independently and only then summed. Changing the output or virtual program does not change the channel settings. Compression on a separate output is retained, and the shared Main effects are bypassed by that separate output. For SF2 in experimental mode the native shared FluidSynth effect sends are taken before the dry compressor; the dry channel is compressed before routing. SFZ native instrument effects, if defined inside the SFZ, remain internal to the instrument. All 96 new host parameters are appended to preserve existing IDs; the six values for each channel persist in `.lsfx` presets and REAPER project state (XML version 13). Backspace resets the selected parameter; Alt+I resets all compressors.

**Normal TEST25 build:** SFZ channel compressors work in the existing isolated render path. SF2 still uses the previously stable stereo FluidSynth renderer and cannot support per-channel audio compression or separate routing until isolated audio rendering is validated. The corresponding SF2 grid rows are hidden in this build; stored/host-automated settings do not affect SF2 audio. Existing hybrid playback is preserved.

**Optional SF2 experimental build:** GitHub Actions > Build LSFX VST3 Windows x64 > Run workflow > enable `experimental_sf2_multigroup`. This compiles the full SF2 per-channel dry compression/routing path and tests it in the console hybrid smoke process before packaging a distinctly named `TEST25-SF2-experimental` artifact. The title marks it experimental. CMake equivalent: `-DLSFX_EXPERIMENTAL_SF2_MULTIGROUP=ON`. The multi-output path previously caused REAPER crashes on Windows; it is not enabled automatically. Test only in a disposable project after the isolated tests pass. No Windows host verification is claimed.
